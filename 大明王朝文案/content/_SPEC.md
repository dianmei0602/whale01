# 《大明王朝》全景内容工程 · 共享规范

## v4.0 内容契约补充

自 v4.0 起，发布数据由 `build_content_bundle.js` 统一生成，客户端不得自行拼装另一套人物或事件数据。

### 人物完整度

- `core`：31 位核心人物，要求第一人称文学重构、完整人生阶段、身后评析和至少一条书目来源。
- `extended`：至少 5 个人生阶段，能够覆盖早年、转折、高峰和结局。
- `standard`：至少 6 条可考事迹和完整基础生平；仍是“人物档案”，不得宣称为与核心人物同等深度。
- 第一人称自述必须标记 `editorialType: literaryReconstruction`，不是史料引文。

### 时间

- 保留原 `date` 作为工作日期，同时生成 `time.precision`：`year / month / day`。
- 只有年份的事件不得在界面显示为精确月份；争议细节写入 `uncertaintyFlags`。

### 地点

- 事件通过 `placeRefs` 关联 `places.json`。
- 关键词推断必须标为 `confidence: inferred`，人工核对后再改为 `verified`。
- 全国性事件可以没有单一地点，界面应明确显示“全国范围”。

### 来源

- 每个重要事件与人物至少关联一条书目来源。
- 当前尚未逐条补全卷次，使用 `locator: null` 和 `status: work-level`。
- 正式发布前必须清理 `content-review-queue.json` 中的待校项。

### 关系

- 关系证据保存 `evidenceEventIds`。
- `shared-events` 与 `curated-rule` 必须区分；共同出场不能自动等同于政治同盟。

### 画像

- `published/portraits.json` 必须覆盖全部人物。
- `historical` 只能用于来源与许可可追溯的传世画像。
- 找不到可靠画像时使用 `fallback`，界面必须标注“档案形象，不冒充历史肖像”。

## 项目背景

沉浸式历史叙事 App《大明王朝》。主轴是「危机 — 应对 — 代价」，三条压力线为**边患线 / 财政线 / 党争线**。已有成果：

- `大明王朝App企划案.md`：五幕结构、三线交错机制
- `大明王朝·深度文案集.md`：31 位核心人物的深度自传（本轮复用，不要重写）
- `大明王朝iOS/index.html`、`大明王朝demo/index.html`：交互原型

本轮目标：把 1351（朱元璋从军）到 1662（永历遇害）之间**所有重要事件**与**所有出场人物**织成一张可检索、可交互的网，并生成《明朝那些事儿》式的分卷叙事大纲。

## 单一 ID 源

`roster.json` 是所有任务的唯一人物 ID 表。任何 `people` 引用**必须**使用其中的 `id` 字符串，不得自造、不得改名、不得使用姓名。已有 31 人标 `existing:true`，其深度自传会被构建脚本自动复用，不需要你撰写。

`span` 是可视化生命线区间：有确切生卒用生卒年，生卒不详用其见于史册的活动区间，`brief` 中注明。

## 阵营枚举（side，严格取值）

帝王 / 宗室 / 后妃外戚 / 宦官 / 文臣 / 武将 / 言官·东林 / 阉党 / 边将·辽东 / 南明 / 方外·其他 / 元末群雄 / 北元·蒙古 / 后金·清 / 日本·朝鲜 / 海盗·倭寇 / 叛将·土司 / 民军·流寇

## 事件类别枚举（cat，严格取值，对应可视化十条泳道）

战役 / 宫斗 / 政变 / 造反 / 暗杀 / 疑案 / 制度 / 财政 / 人事 / 外交

- 战役：对外战争、边患入寇、平叛作战、水战、围城
- 宫斗：立储、后妃争宠、外戚、移宫、国本之争
- 政变：靖难、夺门、废立、逼宫、兵谏
- 造反：宗室叛乱、民变起事、兵变、土司叛乱
- 暗杀：刺杀、毒杀、弑君尝试、廷杖致死、密谋除掉某人
- 疑案：梃击、红丸、妖书、下落不明、死因存疑、大案
- 制度：废相、内阁、卫所、科举、厂卫、封贡、大礼议、京察
- 财政：宝钞、白银、赋役、加派、矿税、漕运、赈灾、治河
- 人事：任免、清算、抄家、党争、建言获罪、殉国
- 外交：下西洋、遣使、册封、和议、互市、援朝、勘合贸易

## 人物档案 schema

```json
{
  "people": [
    {
      "id": "liu_ji",
      "name": "刘基",
      "alias": "字伯温",
      "side": "文臣",
      "years": "1311—1375",
      "span": [1311, 1375],
      "role": "开国谋臣 · 御史中丞",
      "arc": "一句话概括一生弧线，25 字内",
      "bio": "280-420 字连贯生平：出身与早年如何塑造他 → 哪一步选择把他推上舞台 → 权力或功业顶点时他实际能决定什么 → 崩塌或收束 → 身后评价。必须有具体年份与事件，把个人命运挂回边患 / 财政 / 党争三线之一。",
      "deeds": [["1353", "应朱元璋之聘至应天"], ["1371", "告老还乡"]],
      "end": "结局一句话",
      "note": "一句史识点评，不脸谱化、不抒情",
      "threads": ["党争线"],
      "related": ["zhu_yuanzhang", "huweiyong"]
    }
  ]
}
```

`deeds` 6–10 条，`[年份字符串, 事迹]`；年份必须落在 1351–1662 之间，按时间升序。`threads` 取值只能是 边患线 / 财政线 / 党争线，可 0–3 条。`related` 3–6 个 roster 中的 id。

## 事件 schema

```json
{
  "events": [
    {
      "id": "e1449_tumu",
      "year": 1449,
      "date": "1449.8",
      "era": "正统十四年",
      "title": "土木堡之变",
      "cat": "战役",
      "place": "土木堡（今河北怀来）",
      "text": "220-320 字。交代前因、现场的具体抉择、后果与代价；结尾一句钩子连向后续。不虚构对话、不编造心理细节，分析可以有观点但必须给出因果。",
      "people": ["zhu_qizhen", "wangzhen", "yexian", "yuqian"],
      "threads": ["边患线", "党争线", "财政线"],
      "cost": "一句话代价或结构性影响",
      "hook": "一句话连向下一事件"
    }
  ]
}
```

`id` 用 `e` + 年份 + 简短英文/拼音后缀，全局唯一。`year` 为整数，`date` 可写 `1449.8` 或空字符串。`people` 2–7 个 id，必须来自 roster，按与事件的相关度排序。`cat` 严格取自上面的枚举。

## 文风（所有内容统一）

- **《明朝那些事儿》的骨，史识的皮**：叙事有现场、有处境、有转折、有钩子，读得下去；但不戏说、不油滑、不网络梗、不虚构对话与内心独白。
- 史实准确：年份、官职、战役、结局依《明史》《明实录》及主流研究；争议处用「史载」「存疑」「一说」标注，不要写成定论。
- 正面人物不神化，反面人物不脸谱化；宦官、权奸、民军首领都要写成处境与制度的产物。
- 短句为主，克制，少形容词，禁用「赋能 / 无缝 / 新一代 / 悲壮 / 可歌可泣」这类空词。
- 每条内容都要能回答：**这一件事（或这一步选择）给三条线中的哪一条加了压，代价由谁承担**。

## 输出格式（硬性）

- UTF-8 标准 JSON，无注释、无尾逗号，不要用 Markdown 代码块包裹。
- 字符串值内部若需要引号，一律用中文「」，**禁止出现 ASCII 双引号**，避免转义出错。
- 分批写文件：每批 18–25 人 / 25–35 事件，写到 `content/batch/<前缀>_1.json`、`<前缀>_2.json`……每批独立合法 JSON，顶层键分别是 `people` 或 `events`。
- 写完用 `node -e "JSON.parse(require('fs').readFileSync('文件','utf8'))"` 逐文件验证，再用 `node -e` 校验 id 是否都在 roster 中、cat/side 是否合法、deeds 年份是否升序。
- 最后只回报：文件路径列表、条数、校验结果。不要输出正文。
