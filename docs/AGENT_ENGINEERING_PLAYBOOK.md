# Agent 工程与 Skill 使用手册

- 适用版本：鲸鱼 2.0 封版后
- 目标：让后续 Agent 开发可复用、可验证，不把“模型能回答”误当成“产品完成”

## 1. Agent 的职责边界

模型负责：

- 理解目标与风险
- 把任务拆成有依赖的步骤
- 选择工具与参数
- 综合真实工具结果
- 在不完整时追问

本机系统负责：

- 权限
- 工具校验
- 确认与取消
- 真实执行
- 幂等、超时、恢复与回执
- 只有成功后才能显示的完成状态

供应商负责：

- 听写与语言模型
- TTS
- 搜索、行情等外部数据

任何供应商失败都必须显式暴露，不能用模型知识或模拟结果补齐。

## 2. 推荐链路

```text
输入
  → 本地快速意图判断
  → 必要时结构化规划
  → 工具预算与相关工具集
  → 本机权限/确认
  → 工具执行
  → 全失败换路一次
  → 结果审查
  → 最终文字流式回答
  → 回执、工作区与记忆沉淀
```

原则：

1. 工具参数必须完整后再执行。
2. 最终文字可以流式，工具 JSON 不应直接进入用户视野。
3. 工具失败不是任务完成；换路也只能有明确上限。
4. 首字速度靠减少规划等待，而不是把完整回答做打字动画。

## 3. 工具契约设计

### 单一契约源

- 工具名称、技能归属、描述和 JSON Schema 以 `tools.v1.json` 为准。
- `AgentSkill.tools` 从契约派生，不再维护另一套硬编码名称。
- 展示层可以有标题和图标，但不得改变执行权限与参数结构。
- 新增工具必须同时补齐执行路由、权限表、结果展示和测试。

### 工具设计检查表

- 名称表达单一动作
- 参数最少且可验证
- 不要求模型猜测关键参数
- 只读与写入明确分开
- 写入有幂等键
- 超时与“执行结果未知”可区分
- 失败返回可行动的原因
- 工具结果包含来源与时间（适用时）
- 不允许因为工具失败而伪造合理答案

### 最小权限

- 权限在需要时请求，不在启动时批量索取。
- `needs_authorization`、`failed`、`cancelled` 和 `success` 必须区分。
- 打开外部 App 只表示交接，不表示完成导航、播放或发送。

## 4. 规划与预算

### 混合规划

- 简单、稳定问题先用本地启发式判断，直接进入快速回答。
- 复杂、实时、设备操作或多步骤问题再调用结构化规划模型。
- 规划结果只是建议，最终行为以工具契约和真实结果为准。

### 预算

```text
batchBudget = min(10, max(3, taskCount + 2))
```

- 达到预算时列出仍未完成的计划步骤。
- 不允许“无限自我修复”造成不可控时长和费用。
- 每个工具批次都应有稳定回执，可跨重启恢复。

### 换路

只在以下条件同时成立时换路：

- 当前批次工具全部失败
- 任务多于一步
- 本轮尚未换路

换路提示必须禁止原样重试同一工具和参数。权限拒绝、用户取消不属于“技术失败”，不能自动换路绕过。

## 5. 流式回答

- 只有最终用户文字增量可以显示。
- 工具调用参数在协议层拼完整后再解析。
- 停止请求要同时终止 URLSession 任务和 SSE 读取。
- 首字前失败可完整重试；首字后失败必须保留半截内容。
- 半截内容应作为普通助手消息保存，并保留原输入用于重试。
- 1.5 秒是目标，不是未经验证的承诺；必须记录设备、网络和首字时间。

## 6. 本地优先数据

### 分层

- 小偏好：`UserDefaults`
- 对话、记忆、工作区和离线正文：文件或数据库
- 大对象、关系查询和迁移：Repository + 版本化 Schema，必要时 SwiftData
- 密钥：Keychain

### 迁移

- 每次持久化结构变化都要有 schema 版本。
- 解码必须向后兼容旧字段。
- 无法解析的数据先备份，不能静默清空。
- 遇到更高版本数据时应只读，避免降级覆盖。
- 新版本写入后保留上一版备份和迁移测试。

## 7. 工作区与长期记忆

- 工作区必须可被 Agent 检索、写入和跟进，否则只是静态记事本。
- 保存动作不自动等于待办、日程或长期偏好。
- 用户要求“记住”时区分：
  - 一次性工作区记录
  - 可编辑偏好
  - 系统提醒
- 回答“我以前记过什么”必须返回真实保存记录和来源。
- 长期记忆优先保存可解释实体、时间、任务结果和来源，而不是纯字符 bigram。

## 8. 原生阅读器

- 正文抽取失败要明确说明，不能静默跳 Safari。
- Safari 只能作为用户明确选择的兜底。
- 正文与离线缓存需要来源 URL、获取时间和截断状态。
- 重点条目必须能定位到原文段落。
- “为什么重要”只能依据正文中的事实、数字、因果关系或结论，不添加外部推断。
- 阅读状态至少区分待读、在读和读完，并保存进度。

## 9. UI 与交互经验

- 首页不是功能目录，只放高频动作和真实状态。
- 没有真实数据时使用紧凑空状态，不展示“待命”“查看安排”等占位内容。
- 全天日历事件可以出现在今日安排中，但不应自动成为主任务。
- 主任务卡片只保留：类别、标题、必要时间、下一步。
- 长分析默认折叠；用户明确展开后仍限制高度并支持内部滚动。
- 写操作先展示可编辑预览，再执行。
- 语音结果回填草稿，不自动发送。
- 所有关键动作需要触感、文字状态和 VoiceOver 描述。

## 10. 测试策略

### 本地

- Swift 全文件语法解析
- JSON Schema 与技能引用校验
- `git diff --check`
- 迁移与纯逻辑单元测试

### CI

- App 与测试目标真实编译
- 单元测试
- 导航、草稿、首页和外观 UI 回归
- IPA 源码 SHA、GUID、讯飞字段、哈希和架构校验

### 真机

- 麦克风、语音识别和音频路由
- EventKit、HealthKit、MusicKit 权限
- 分享扩展和 App Group
- App Intents、Siri 和 Spotlight
- 小组件、锁屏与深链
- 流式首字、断网半截、停止与恢复

模拟器通过不等于真机完成。CI 失败时先看第一个真实 `error:`；runner 未分配、模拟器启动失败属于基础设施失败，不能误报为代码失败。

## 11. Skill 使用逻辑

### 什么是 Skill

Skill 是工作方法和领域约束，不是工具本身。它告诉 Agent：

- 何时开始
- 先读什么
- 哪些行为禁止
- 如何验证
- 哪些交付证据必须保留

真正执行依赖仓库代码、CLI、MCP、App Intents 或外部 API。

### 选择顺序

1. 用户明确点名的 Skill
2. 与任务直接匹配的领域 Skill
3. 通用工程流程 Skill
4. 没有匹配时直接使用仓库与工具

不要为了“用了 Skill”而加载无关 Skill，也不要用 Skill 描述代替源码检查。

### 使用步骤

1. 完整读取 `SKILL.md`。
2. 读取它指定的必要参考资料。
3. 检查仓库、分支、工作区改动和项目约束。
4. 只执行与当前任务相关的步骤。
5. 运行 Skill 要求的验证。
6. 在结果中区分已执行、已验证和未验证。

### 项目 Skill

鲸鱼开发优先使用 `nomi-project-maintainer`：

- 保持钛金属鲸鱼、蓝眼睛、拖拽与物理效果
- 保持三个主入口
- 权限按需请求
- 系统音乐库不恢复文件导入
- 行情只读、有延迟和风险提示
- 不伪造完成、授权、新闻或支付结果

涉及 Siri、快捷指令或小组件时，再使用 `ios-app-intents`。只做最小 Intent 面，不让每个页面都变成一个 Intent。

### Agent 提示词

给执行 Agent 的任务应包含：

- 用户真正目标
- 可修改范围
- 必须保留的产品边界
- 验收标准
- 测试与构建方式
- 是否允许提交、推送或发布
- 失败时如何报告不确定性

禁止用模糊的“优化一下”替代验收标准；也不要在未编译时声称完成。

## 12. 多 Agent 协作

- 只在用户明确要求或项目 Skill 要求时使用子 Agent。
- 同一文件只允许一个写入者。
- 重叠文件由主 Agent 集成，子 Agent 做只读审查。
- 每个子任务必须有独立、可验证的交付物。
- 主 Agent 最终负责 diff、测试、构建和用户交付。

## 13. 发布与保存

- 未经明确授权不推送、不打标签、不触发发布。
- IPA 文件名包含源码短 SHA。
- 分开保存 manifest、SHA256 和安装包。
- 含个人 API 凭据的 IPA 仅允许个人侧载。
- 版本日志必须记录源码 SHA、运行编号、测试结果、文件大小和哈希。
- 历史封版日志只追加，不覆盖；后续版本另建日志。
