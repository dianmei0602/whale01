# Nomi 方案 C · iOS 落地规范

## 0. 不可破坏的角色资产

钛合金机器人本体、眼睛参数、表情和动作是 Nomi 的核心产品资产，不是可替换的装饰图标。

实施时必须保留：

- `PetCharacterView`、`PetCharacterCanvas` 和现有钛合金材质绘制；
- 所有现有表情、眨眼、视线跟随、说话时表情节拍；
- 点击、长按、看见用户、物理盒子等角色交互；
- 不同尺寸下正确的头身比例，不能把整个角色压成一个矩形头像。

使用层级：

| 场景 | 使用方式 |
|---|---|
| App 主界面、对话、首屏 | 完整 Nomi 角色，建议 96–132 pt |
| 对话回答、语音状态 | 完整或半身 Nomi，建议 52–88 pt |
| 顶部头像、输入栏、聊天气泡、设置页头像 | 黑底双蓝眼小图标，24–36 pt |
| 锁屏 Live Activity | 完整或半身 Nomi，建议 60–96 pt |
| 小组件 | 完整角色缩小版，建议 42–62 pt |
| 灵动岛 compact / minimal | 只允许使用眼睛局部符号 |

黑底蓝眼小图标用于 App 内所有小头像；它不能代替首页、对话和锁屏中的完整钛合金角色。任何布局调整都必须先给完整 Nomi 预留视觉位置。

## 1. 设计目标

Nomi 是“安静陪伴的私人助理”，不是聊天记录容器，也不是功能仪表盘。

每个界面只承担一个主要问题：

- Nomi：现在最值得做什么？
- 今日：今天是什么节奏？
- 对话：我如何让 Nomi 替我完成一件事？
- 锁屏 / 小组件 / 灵动岛：现在是否需要我处理？

默认行为：

- 先给出结论，再提供最多两个动作。
- 数据必须有来源和更新时间。
- 写日历、取消、预订和支付必须先确认。
- 不为了“陪伴感”持续动画、持续通知或制造焦虑。

## 2. 信息架构

```text
Nomi
  ├─ 当前最重要事项
  ├─ 两个直接动作
  ├─ 高优待办
  ├─ 当天时间线摘要
  └─ 对话输入坞

今日
  ├─ 下一事项
  ├─ 完整议程
  └─ 权限/数据状态

设置
  ├─ 声音与主动提醒
  ├─ 隐私与数据
  ├─ 记忆
  ├─ 系统权限
  └─ 高级
```

设置从头像进入，不占主导航。对话是任务流程的一部分，不使用单独的永久 Tab。

## 3. 视觉 Token

### 浅色

| Token | 值 | 用途 |
|---|---|---|
| `ground` | `#F1F8FF` | 页面底色 |
| `surface` | `#FFFFFF` | 卡片、输入坞 |
| `surfaceSoft` | `#DFEEFF` | 次要块、完成按钮 |
| `ink` | `#142338` | 主文本 |
| `muted` | `#5E7184` | 次级文本 |
| `blue` | `#147FE8` | 主要数据/进行中 |
| `navy` | `#17314D` | 重点卡 |
| `amberSoft` | `#FFF2D8` | 警告/待处理 |

### 深色

| Token | 值 | 用途 |
|---|---|---|
| `ground` | `#121B24` | 页面底色 |
| `surface` | `#1A2530` | 卡片 |
| `surfaceSoft` | `#21303D` | 次级块 |
| `ink` | `#F4F8FB` | 主文本 |
| `muted` | `#B3C1CD` | 次级文本 |
| `blue` | `#78C7FF` | 主要数据/进行中 |
| `navy` | `#DCEFFF` | 反色重点块 |

### 字体与尺寸

- 系统字体：SF Pro Rounded 用于品牌和标题，正文回退 SF Pro / PingFang SC。
- App 页面标题：28–34 pt。
- 卡片标题：18–22 pt。
- 正文：14–16 pt。
- 辅助文字：12–13 pt，最小不低于 11 pt。
- 数字使用等宽数字：`font-variant-numeric: tabular-nums` 或 `.monospacedDigit()`。
- 触控区域最小 44×44 pt。

### 圆角与间距

- 重点卡：24–28 pt。
- 普通卡：18–22 pt。
- 控件：12–14 pt；主要动作使用胶囊或 14 pt 圆角。
- 页面左右边距：20 pt。
- 组件间距：8 / 12 / 16 / 24 pt。
- 同一屏幕最多使用三种圆角尺寸。

## 4. 主应用组件

### `NomiAvatar`

- 黑色大圆角底，中央两只发光蓝眼。
- 尺寸：24 / 28 / 32 / 36 pt。
- 眼睛颜色和开合跟随当前 `PetExpression`，但不替代完整角色。
- VoiceOver 名称由上下文提供，例如“Nomi，正在听”，不重复朗读装饰图形。

### `PrimaryActionCard`

- 深蓝色字段，不使用渐变。
- 信息顺序：时间/地点 → 事件名称 → 一句准备提示 → 操作。
- 最多两个动作：一个主要，一个次要。
- 不显示超过一行的说明；详细内容进入对话或详情。

### `TaskRow`

- 圆形完成控件 + 两行文字 + 可选文字按钮。
- 逾期只把日期文字改为警告色，不把整行染红。
- 完成后保留短暂“已完成”回执，避免状态突然消失。

### `TimelineRow`

- 时间列宽度 42–48 pt。
- 当前事项用蓝点，过去事项降低文字对比度。
- 事件超过 2 行时省略，完整信息进入对话或详情。

### `NomiComposer`

- 固定底部，高于导航条。
- 左侧 32 pt Nomi 头像，中间文本，右侧语音按钮。
- 有字时右侧按钮切换为发送。
- 语音状态切换不要改变整体布局。

### `ConfirmationCard`

- 用于取消、改期、下单、支付。
- 必须显示对象、原值、新值、金额/时间、冲突或风险。
- 默认按钮为“先不改”，风险按钮明确写出动作。
- 高风险动作必须由后端或本地策略再次验证。

## 5. 锁屏设计

### 结构

```text
时间 / 日期
小型锁屏组件（Nomi、天气）
Live Activity
  ├─ Nomi 头像
  ├─ 事件名称和时间
  ├─ 倒计时
  ├─ 一行准备提示
  └─ 最多两个动作
```

### 原则

- 锁屏只显示一个需要行动的事实。
- 没有事件时，不持续占用锁屏。
- 不通过长时间动画吸引注意。
- 点击整块进入 `nomi://today`；动作按钮进入事件或确认流程。

## 6. 灵动岛设计

### 紧凑态

- 左侧：两只蓝色眼睛。
- 右侧：倒计时，如 `22m`。
- 不显示完整事件名，避免系统裁剪。

### 展开态

- 左侧：Nomi 头像。
- 右侧：倒计时。
- 下方：事件名、地点、一行行动建议。
- 最多两个动作：查看材料、出发。

### 最小态

- 只保留 Nomi 眼睛符号。
- 不使用文字。

### ActivityKit 限制

- 只能使用 SwiftUI 的有限视图，不能嵌入 WebView、视频、Lottie 或自绘 Canvas 动画。
- Live Activity 最长 8 小时，系统可提前结束。
- 更新频率由系统预算控制，不保证逐秒刷新。
- 不得通过静音音频让 App 常驻后台来驱动灵动岛动画。
- 状态变化应发生在有意义的时间点：开始、10 分钟前、5 分钟前、事件开始、事件完成。

### 生命周期

```text
事件前 30 分钟：开始 Live Activity
事件前 10 分钟：更新倒计时和“准备出发”
事件前 5 分钟：更新“现在出发”
事件开始：更新“进行中”
事件结束 / 点击完成：结束并生成回执
异常或过期：设置 staleDate，展示“状态待确认”
```

## 7. 小组件

### 小号

- Nomi 头像。
- 倒计时 `22m`。
- 一行事件名称。

### 中号

- Nomi 头像和「今天」。
- 下一项事件。
- 地点和准备状态。

### 数据要求

- 正式版使用 App Group 共享快照，例如 `group.com.jinri.app`。
- 快照字段至少包含：下一事件、开始时间、地点、准备状态、来源、更新时间、是否需要用户确认。
- 小组件只展示快照，不直接执行日历写入。
- 无共享容器时，必须明确降级，不允许展示过期或猜测的数据。

## 8. 深链

```text
nomi://open
nomi://today
nomi://event/<event-id>
nomi://prepare/<event-id>
nomi://chat
nomi://confirm/<action-token>
nomi://settings/privacy
```

所有深链必须验证 scheme、host 和 action token；未知参数回退到 Nomi 首页。

## 9. 数据与安全

- 锁屏和小组件不显示完整地址、健康指标或乘客身份。
- 组件不包含 API Key、支付信息或可修改订单的长期 token。
- 操作 token 短期有效、一次性使用。
- 模型不直接持有用户账号、支付凭据或后台密钥。
- 日志脱敏，不记录完整聊天、精确地址和健康原始值。

## 11. 验收标准

- [ ] 用户 5 秒内能说出当前最该做什么。
- [ ] 首屏不出现无法行动的多余统计。
- [ ] 取消、改期、预订和支付都有确认卡。
- [ ] 锁屏和灵动岛只展示一个核心事项。
- [ ] 灵动岛在紧凑、展开、最小三种状态下都可读。
- [ ] 小组件与 App 的事实、来源和时间一致。
- [ ] 无权限、空数据、断网都不显示假信息。
- [ ] 深色/浅色模式都通过文字对比度检查。
- [ ] VoiceOver 能读出 Nomi 状态、事件、时间和操作。
- [ ] Dynamic Type 放大后，核心操作不被遮挡。
- [ ] 没有依赖静音音频维持后台运行。
- [ ] ActivityKit 更新点不超过系统合理预算。
