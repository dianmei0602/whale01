# Nomi 1.2 信息板块扩展能力图

日期：2026-11-14

实施状态：`intel-navigation`、`hot-lists`、`market-lab`、`ai-vendors`、
`game-radar` 已完成本地实现；`game-metrics` 和 `wechat-game-media`
仍等待授权数据源。

## 需求解释

本次扩展包含多个可以独立上线的数据能力，不应作为一个大页面一次硬塞完成。

对用户原话的解释：

- “资金往来”先按股票的资金流向（主力、超大单、大单、中单、小单）实现。
- “期待帮”按 Steam 期待榜/即将发售榜实现。
- “数据大模型”按基础模型、数据模型和模型发布动态分类。
- “微信公众号”不能未经授权抓取，首版只接公开 RSS 或授权内容源。
- “预估下载量和收入”没有可靠公开统一口径，必须有商业数据源才能展示数字。

## 能力模块

| 模块 id | 责任 | 能直接使用的数据 | 依赖 |
|---|---|---|---|
| intel-navigation | 首页新增知乎、游戏入口；情报中心扩展到六页横滑 | 现有 UI、微博、要闻、股票、AI | — |
| hot-lists | 微博热搜、知乎热榜 | 微博公开接口、知乎 hot-list API 已验证 HTTP 200 | intel-navigation |
| market-lab | 资金流向、板块、个股详情、股本/股东、财报 | 东方财富公开接口已验证 HTTP 200 | intel-navigation |
| ai-vendors | Codex、Claude、DeepSeek、豆包、基础模型动态 | OpenAI RSS 已验证；其余使用现有中文科技源和官方公开页的可用部分 | intel-navigation |
| game-radar | 游戏新闻、Steam 排行、App Store 免费/畅销榜、游戏详情 | 游研社 RSS、App Store RSS 已验证；Steam 当前网络超时 | intel-navigation |
| game-metrics | 预估下载量、收入 | 当前无可靠公开接口；需 Sensor Tower、data.ai 等授权数据 | game-radar + 数据供应商 |
| wechat-game-media | 指定微信公众号的游戏文章 | 无稳定公开 API；需授权聚合、运营后台或人工精选链接 | game-radar + 内容授权 |

## 建议构建顺序

1. `intel-navigation`
2. `hot-lists`
3. `market-lab`
4. `ai-vendors`
5. `game-radar`
6. `game-metrics` 与 `wechat-game-media` 在数据源确认后接入

`game-metrics` 和 `wechat-game-media` 不能阻塞前五个模块上线。

## 产品结构

首页仍保持三个底部主入口。信息入口扩展为 2×3 大卡片：

1. 时事新闻
2. AI 科技
3. 股票行情
4. 微博热搜
5. 知乎热榜
6. 游戏动态

情报中心扩展为六页全屏横滑：

`时事 → AI → 股票 → 微博 → 知乎 → 游戏`

## 股票详情

点击任一指数或个股进入全屏详情页，内部使用二级标签：

- 概览
- 资金
- 板块
- 财报
- 股权

必须显示数据来源、报告期和更新时间。没有权限、非 A 股或供应商不返回的字段显示“暂无数据”，不能推算。

## AI 厂商

AI 页面使用筛选项：

- 全部
- Codex / OpenAI
- Claude
- DeepSeek
- 豆包
- 基础模型

首版只展示实际抓到的标题、摘要、来源和链接。官方 RSS 缺失的厂商通过现有中文科技源关键词检索，不伪造官方发布。

## 游戏页

游戏页二级标签：

- 新闻
- Steam
- 期待榜
- 手游免费榜
- 手游畅销榜

点击游戏进入详情：

- 来源
- 排名
- 平台
- 开发商/发行商
- 简介
- 价格或免费状态
- App Store 评分、类别、版本、更新时间
- 外部商店链接

Steam 当前环境访问超时，因此必须设计为独立失败模块；后续可以通过用户可访问的代理或自有服务端网关增强。

## 下载量与收入

当前不接入估算数字。原因：

- Apple/Steam 官方榜单不提供下载量和收入。
- 第三方估算存在口径差异。
- 没有授权时，客户端不能自行编造或套用固定倍率。

正式接入时需要：

1. 选择授权供应商。
2. 明确是月下载、总下载、内购收入还是广告收入。
3. 显示估算平台、统计周期和“第三方估算”标签。

## 微信公众号

不直接抓取搜狗微信或公众号页面。可选方案：

- 运营后台人工维护精选链接。
- 使用已授权 RSS/内容聚合源。
- 使用微信开放平台且取得对应权限。

在方案确定前，游戏新闻先使用游研社等公开 RSS。

## 验收原则

- 每个数据模块独立加载、独立失败。
- 每项数据必须显示来源和更新时间。
- 不展示假下载量、假收入、假资金或假财报。
- 六页可以左右滑动，也能通过顶部标签跳转。
- 现有 Nomi 角色、三个底部主入口、音乐和本地数据约束不变。

## 需要确认的产品范围

建议首版按“个人自用、公开数据和授权链接优先”执行：

- 直接接入知乎、微博、股票 F10、App Store 和公开游戏 RSS。
- Steam 保留真实请求和独立失败提示。
- 下载/收入和微信公众号先显示“等待数据源”，不做假数据。

如果需要正式商业分发，则应先购买行情、游戏估算和内容授权，再进入这些模块。
