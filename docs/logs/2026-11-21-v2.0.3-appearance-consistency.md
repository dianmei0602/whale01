# 2.0.3 外观一致性修正

- 日期：2026-11-21
- 版本：`2.0.3 (203.x)`
- 目标：让设置里的配色预览、App 实际渲染色和系统表单外观保持一致

## 问题定位

“配置颜色和 App 不一致”不是单一色值错误，主要来自四处：

1. 设置页展示固定参考色，其中夜海和鎏金的近黑色已经不代表 2.0.2 实际深色背景。
2. 配色解析在颜色闭包中直接读取 `UserDefaults`，但这不是 SwiftUI 能观察的状态依赖。
3. `UITabBarAppearance` 和 `UINavigationBarAppearance` 只在 App 启动时设置一次。
4. 收藏、待办编辑、开发设置等系统 `Form`、`List` 仍会露出系统背景、系统次级文字和系统强调色。

## 修正内容

### 真实界面预览

- 配色卡不再显示四块固定“海报参考色”。
- 每张卡显示当前日间或夜间真实使用的页面底色、卡片色、主操作色、提示色和文字色。
- 明暗模式卡也使用当前配色的真实明暗结果，而不是固定的黑白色块。
- 副标题明确颜色职责，例如“夜海蓝操作 · 沙漠红提示”。
- VoiceOver 会读出每套主题的实际用途。

### 切换与持久化

- 新增 `WhaleAppearanceStore`，由可观察状态持有当前配色。
- 设置页显式接收同一个 `WhaleAppearanceStore`，不依赖 sheet 边界自动继承，避免打开设置时对象缺失。
- 选择主题时先保存到 `UserDefaults`，再发布状态，避免界面重建时仍读到旧值。
- 设置页在主题变化时整体重绘，因此页面底色、卡片、预览和选中边框不会出现一帧或多帧的混搭。
- 主页面以配色作为刷新边界；从设置切回 App 时，全部页面会使用新配置重新渲染。
- 导航栏和 TabBar 的 UIKit appearance 会随主题同步刷新。

### 残留系统色

- 收藏与稍后读改为主题卡面和背景。
- 待办详情、智能排期、转待办、补充提醒时间、常用操作和开发设置移除系统默认列表背景。
- “已复制”悬浮提示改用主题卡片、文字、边框和阴影色。
- 微博热榜排名与标签改用主题前景色。
- 语音主按钮改用主题按钮文字色。
