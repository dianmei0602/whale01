## 2. 产品定位

Nomi 是住在 iPhone 里的助理宠物。它不是一个普通聊天列表，而是由钛合金角色、主动提醒、日程、待办、新闻和音乐共同组成的个人助理入口。

当前 App 有三个主入口：

- 对话
- 待办
- 设置

对外部服务的定位：

- DeepSeek 用于自然语言对话和复杂意图理解。
- 日程、提醒事项、天气、步数、音乐和新闻使用真实系统能力或公开数据。
- 没有实现的动作必须明确说明，不能伪造成功状态。
- 订票、酒店预订、外卖和支付尚未接入；当前只能提供信息、计划或外部跳转，不能宣称已经完成交易。

## 3. 不可破坏的产品约束

以下要求来自用户的实际反馈，应视为产品约束，而不是普通样式偏好：

1. 保留钛合金 Nomi 本体、黑色玻璃脸、蓝色竖眼、表情、眨眼、视线跟随、拖动和物理交互。
2. 黑底双蓝眼小头像只用于小尺寸标识，不能替代完整角色。
3. 完整 Nomi 仍是主界面的角色主体；对话页默认隐藏完整角色时，必须能从聊天顶栏重新显示。
4. 三个入口只出现一次，不在输入区或首页重复堆叠入口。
5. 首页和对话页使用完整统一的极光背景，不能出现白色断层、切面或多余矩形底板。
6. 跟手左右滑动必须能切换主入口；键盘出现时底部托盘隐藏，点空白、下滑和发送时能收起键盘。
7. 设置按类别进入子页，不把所有选项平铺在一页。
8. 权限按使用场景请求，不在首次启动时批量弹窗。
9. 音乐读取 iPhone「音乐」资料库，不恢复文件导入。
10. 音乐播放不能占用灵动岛，也不能接管系统 Now Playing 状态。
11. 新闻必须是中文，并在 Nomi 内打开原文，不能跳到外部浏览器。
12. 每日鼓励文案必须每天随机，连续 30 天不重复。
13. 锁屏 Live Activity 与主屏/锁屏组件必须保留；没有共享数据时只能显示真实降级状态，不能显示旧数据或编造日程。
14. 没有用户明确命令时，只提交本地改动，不执行 `git push`。

- 钛合金 Nomi 与完整表情系统。

- 今日新闻入口。

- EventKit：日历与提醒事项。
- CoreLocation：按需定位。

- Speech：语音识别与系统语音。
- MediaPlayer：读取系统音乐资料库。
- WidgetKit：主屏小/中号组件、锁屏圆形/矩形/行内组件。
- ActivityKit：锁屏 Live Activity 与灵动岛。
- UserNotifications：早报、会前、久坐、下雨和就寝提醒。

## 7. 已知限制与风险

### 上架前必须处理

- 讯飞语音密钥目前内置在 App 源码中。当前私有仓库和自用侧载可控；公开源码或上架前应轮换密钥并改用安全配置。
- 当前 IPA 未签名。正式分发需要 Apple Developer 签名、TestFlight 或 App Store 流程。
- 还没有自动化 UI 测试和真机性能基线。

### 免费签名限制

- 免费 Apple ID 每 7 天需要重签。
- 免费签名无法稳定使用 App Group，主屏/锁屏组件可能只显示「打开 App 同步」。
- 免费签名不包含 APNs 和完整 HealthKit 能力。

### 功能边界

- 订票、酒店、餐厅预订和支付没有真实交易后端，也没有支付授权链。
- `nomi://confirm/<token>` 还没有一次性 token 校验。
- Live Activity 受系统刷新限制，不做逐秒动画。
- 新闻依赖公开 RSS，源站改版或限流时需要重新验证。

## 9. 关于团队协作 Agent 的结论

当前阶段不建议再启动多个长期自治 Agent 同时改同一套 SwiftUI 工程。收益不足以抵消合并冲突、重复上下文和规则漂移。

更合适的三层协作方式是：

1. 仓库内的 `AGENTS.md`：所有 Agent 必读的项目边界。
2. 项目专用 Skill：固化 Nomi 的验证、构建和发布流程。
3. 临时只读子任务：只在需要代码审查、新闻源验证或方案比较时使用，由主 Agent 汇总和落盘。

并行开发时一次只能有一个写入者；其他 Agent 做只读分析。若必须并行写入，应使用独立 worktree 和不同文件范围。
